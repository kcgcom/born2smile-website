# dental-search

루트 및 대상 AGENTS.md를 따른다. 실행 전 [준수 정책](../../../docs/marketing/compliance.md)과 [공통 컨텍스트](../../../docs/marketing/context.md)를 이 순서로 확인한다. 기존 자료로 답할 수 없는 중요한 사항만 질문한다.

대상 URL·검색엔진·기간을 정하고 기존 코드와 공개 결과를 대조한다. 기술 점검 시 [lib/AGENTS.md](../../../lib/AGENTS.md)와 실제 SEO 구현을 따른다. 검색 유입은 측정 정의 검증이나 공급자 간 수치 대조가 필요할 때 dental-analytics를 추가한다. AI 답변·인용 검증에는 [AI 검색](references/ai-search.md), 지도·로컬 프로필이나 지역 검색 노출 감사에는 [지역 검색](references/local-seo.md)을 읽는다. AI 답변에 주소·시간이 언급된 경우에는 AI 검색 절차만으로 시작한다. 확인된 문제와 가설을 구분하고 영향·근거·수정 방향을 보고한다. 순위나 인용을 보장하지 않는다.

- 유입 감소는 비교 가능한 완료 기간의 클릭·노출·CTR·평균 순위로 분해한다. 사이트 전체와 페이지·검색어·기기별 변화를 대조하고, 측정 변경·계절성·검색 결과 구성·배포 및 색인 변경을 후보로 잡는다. 집계 평균이 안정적이어도 하위 그룹의 변화를 확인한다.
- 기술 감사에서는 접근 → 색인 → 관련성 순으로 확인한다. 최종 응답과 리다이렉트 체인, sitemap URL, canonical 및 렌더링 결과를 같은 대표 URL에 대조한다. JSON-LD가 템플릿에 있는지와 응답에 실제 출력되는지를 구분한다. 공개 응답이나 색인 자료가 없으면 코드 관찰로 범위를 표시한다.

결과는 [리서치 계약](../../../docs/marketing/research-contract.md)에 맞춰 근거·한계·승인 필요 여부를 기록한다.
