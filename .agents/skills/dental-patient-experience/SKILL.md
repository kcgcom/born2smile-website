# dental-patient-experience

루트 및 대상 AGENTS.md를 따른다. 실행 전 [준수 정책](../../../docs/marketing/compliance.md)과 [공통 컨텍스트](../../../docs/marketing/context.md)를 이 순서로 확인한다. 기존 자료로 답할 수 없는 중요한 사항만 질문한다.

환자 목적과 실제 동선을 정의하고 정보 명확성, 진료시간·위치·연락처 정확성, 모바일 접근성, 불필요한 단계와 오류를 점검한다. 기술 UI 감사에는 website-ui-audit를 필요할 때 선택한다. 작은 표본에서 A/B 효과를 단정하지 말고 정성 검사와 측정 가능한 가설을 우선한다. 불안 조성, 허위 긴급성, 치료 유도, 과도한 CTA 및 민감정보 추가 수집을 금지한다. 실제 문의나 예약을 실행하지 않는다.

- 페이지별로 시작 화면·기기·환자 목적·완료 조건과 관찰한 단계 수를 기록한다. 문의나 예약 완료 대신 링크 발견, 올바른 대상 확인, 필요하면 fixture에서 클릭 이벤트 발생까지 확인한다.
- 개선안에는 마찰의 위치, 변경 가설, 주요 지표의 분모와 성공 기준을 넣는다. 문의 지표와 함께 진료시간 도달, 오류, 접근성 등 악화 여부도 본다. 키보드, 포커스, 터치 영역 등 기술 검사가 필요한 경우에만 UI 감사로 확장한다.

결과는 [리서치 계약](../../../docs/marketing/research-contract.md)에 맞춰 근거·한계·승인 필요 여부를 기록한다.
