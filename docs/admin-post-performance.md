# 포스트 성과 패널과 운영 개요

2026-11-14 배포 준비 기록. 선택형 이유 제거와 함께 운영 반영할 변경이며, 이 기록 작성 시점에는 main 병합 전이다. 기존 포스트 편집·발행·예약 기능을 유지하는 첫 단계 개편이다.

## 포스트 성과 패널

포스트 목록의 각 글에서 **성과** 버튼을 누르거나 `/admin/content/posts?performance=<slug>`로 진입한다. 수정·예약 입력 상태는 그대로 두고 모달을 연다. Escape·닫기 후 포커스를 돌려주며, 본문·제목 편집과 실제 페이지/미리보기로 이동할 수 있다.

- 공개 글만 분석을 조회한다. 초안·예약 글은 공개 전 안내를 표시하고 외부 성과 API를 호출하지 않는다.
- 검색·GA4 방문·PostHog 읽기는 선택한 글을 직접 필터링한다. 상위 글 목록에 없다는 이유로 0을 만들지 않는다.
- 30일/90일 선택은 검색 반영 지연을 고려해 KST 오늘의 3일 전까지 동일한 날짜 범위를 사용한다. 검색 API는 PT, GA4는 속성 시간대, PostHog는 KST로 집계하므로 이를 화면에 표시하며 출처를 섞어 전환율을 만들지 않는다.
- DB 누적 해결·미해결·총 응답과 응답 중 해결 비율은 기간별 분석과 별도 구역에 둔다. 응답 없음은 0% 대신 ‘응답 없음’이다.
- 읽기 표본 수와 추정 읽기율, 본문 방문 중 공유 동작, 글 이용 후 문의 시도를 함께 본다. 문의 시도는 통화·예약 완료나 인과 효과가 아니다.
- 출처별 미설정/오류/정상 조회를 구분한다. 한 출처가 실패해도 다른 출처는 표시하고, 실패를 0으로 바꾸지 않는다. 기간이 바뀌면 이전 기간 수치를 숨긴다.
- 카드 노출·클릭의 별도 집계 표는 이번 범위에 포함하지 않는다.

## 운영 개요

`/admin/operations/overview`를 다음 세 영역으로 정리했다.

1. **지금 처리할 일:** 데이터 조회 실패와 색인 검사/점검 작업 실패. 미색인이나 상태 변경 대기만으로 오류라고 판단하지 않는다.
2. **검토할 콘텐츠:** 미발행 초안, 반복된 미해결 응답, 검색 클릭 감소 후보. 각 글의 편집 또는 성과 패널로 연결한다.
3. **가까운 일정:** 앞으로 14일 내 예약 글과 설정된 휴진·변경 진료시간. 지난 일정은 제외한다.

큰 검색/전환 수치 카드와 분석 바로가기는 상세 분석 링크로 정리했다. 기존 분석 화면과 메뉴는 유지한다.

후보 선정은 운영용 초기 기준이며 통계적 유의성이나 콘텐츠 품질 판정이 아니다.

- 미해결 후보: 누적 응답 5건 이상, 미해결 3건 이상인 공개 글. 최대 3개를 보여준다.
- 검색 후보: 최근 30일과 이전 30일 모두 기록이 있는 글 중 이전 클릭 10회 이상, 5회 이상 감소, 30% 이상 감소. 현재도 공개된 글만 최대 3개 표시한다.
- 현재 기간에서 사라진 행을 임의로 0으로 바꿔 검색 감소 후보를 만들지 않는다. API 결과가 잘린 경우에도 후보 판정을 보류한다.
- 초안은 검토할 작업이지 오류가 아니다. 조회 실패 상태에서 ‘후보 없음’이나 ‘일정 없음’을 표시하지 않는다.

검토 완료 표시, 본문 수정 전후 응답 분리, 자동 글 점수·노출 순위 변경은 이번 범위가 아니다.

## 구현과 검증 경계

- [글별 조회 API](../app/api/admin/blog-posts/[slug]/performance/route.ts): 관리자 인증 후 slug·기간 검증, DB의 현재 글 상태 조회, 기존 캐시 헬퍼 재사용. 부분 실패 결과는 정상 결과로 캐시하지 않는다.
- [성과 집계](../lib/admin-post-performance.ts): 공급자별 병렬 조회, 누적 응답과 기간별 데이터 분리.
- [성과 패널](../app/admin/(dashboard)/components/blog/PostPerformancePanel.tsx): 선택 시 지연 로드, 공통 모달 키보드 동작 재사용.
- [운영 개요](../app/admin/(dashboard)/components/GrowthOverviewPanel.tsx), [후보 기준](../lib/admin-overview.ts), [검색 변화 API](../app/api/admin/search-attention/route.ts).
- DB 마이그레이션이나 운영 데이터 변경은 없다. 기존 선택형 이유 제거 로컬 변경을 보존했다.

실제 읽기 전용 조회에서 Search Console·GA4·PostHog·DB 연결이 모두 정상 응답했고 검색 변화 비교 조회도 정상 실행됐다. 조회 내용·검색어 원문·계정 식별자는 이 문서에 기록하지 않는다.

## 검증 결과

- TypeScript, lint, 프로덕션 build 각각 성공.
- 편집·예약·새 화면 회귀 42개 통과. 검색 변화 후보 연결 후 성과 패널·운영 개요·예약·읽기 관련 최종 회귀 31개 통과.
- 패널의 최초 지연 로딩, 기간 변경 시 이전 값 숨김, 초안 외부 조회 생략, 부분 실패, Escape와 포커스 복원, 예약 날짜 입력 보존을 확인했다.
- 운영 개요의 오류 복구, 표본 기준, 지난/먼 일정 제외와 모바일 가로 넘침을 확인했다. 화면 검증은 모의 데이터로 수행했으며 저장 작업은 하지 않았다.
- 별도로 실제 집계 코드의 네 서비스 연결과 검색 두 기간 비교를 읽기 전용으로 확인했다.
- 배포 브랜치 최종 전체 회귀 187개와 TypeScript·lint가 통과했다. DB 변경은 없으며, 실제 운영 배포 완료는 PR과 Vercel 상태로 확인한다.
