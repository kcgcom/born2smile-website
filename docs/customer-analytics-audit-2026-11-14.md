# PostHog 수집 상태 점검 — 2026-11-14

상태: 실제 API의 읽기 전용 집계 완료. 앱·DB·PostHog 설정·대시보드 변경 없음.

## 조사 조건

- KST 2026-10-15 00:00 이상 ~ 2026-11-14 00:00 미만, 완료된 30일.
- UTC 범위: 2026-10-14 15:00 이상 ~ 2026-11-13 15:00 미만.
- 최초 조회 시각: 2026-11-14T07:42:02.064Z. 이후 같은 고정 기간으로 교차 집계.
- 저장소의 기존 PostHog 조회 설정을 사용해 `/api/projects/:project_id/query/`로 HogQL 조회. 키·프로젝트 ID·원시 방문자·세션 ID는 기록하지 않음.
- 첫 조회는 프로젝트 전체를 점검하고, 상세 조회는 `$host IN ('www.born2smile.co.kr', 'born2smile.co.kr')`로 제한.
- 요청 11회 중 10회 성공. 일별 집계 최초 1회는 날짜 함수 호출 형식으로 HTTP 400, `toDate(toTimeZone(timestamp, 'Asia/Seoul'))`로 수정 후 성공. 인증 오류는 없었음.
- 관리자가 아닌 실제 고객만을 식별한 데이터가 아니다. SDK 관리자 제외가 작동하도록 작성되어 있지만, 관리자 표시가 없는 직원 방문이나 자동화 방문을 이번 집계로 완전히 판별할 수는 없음.

## 3. 수집과 관리자 집계의 차이

| 발견 | 관찰/코드 근거 | 처리 결정 |
|---|---|---|
| 하단 전화 클릭 누락 | `footer_phone_click` 1건이 있으나 현재 CTA/전화 이벤트 목록에 없음 | 전체 전화 의도 목록에 포함 |
| 문의 안내와 실제 연락 동작 혼합 | 현재 CTA 27건 중 문의 안내 이동 14건, 전화 13건 | 안내 이동과 전화·카카오를 별도 표시 |
| 실제 전화 동작 기준 | 하단 포함 전화 14건, 고유 12세션; 카카오 이벤트 0건 | 14회를 통화/예약으로 부르지 않음 |
| 블로그 문맥 유실 | 블로그에서 발생한 플로팅 문의·하단 전화 각 1건은 `page_type=global` | 전역 버튼 위치와 현재 페이지 종류 분리 |
| 좋아요 범위 불일치 | 상세는 이벤트 코드 존재, 목록은 없음 | 성공한 목록 좋아요에도 이벤트 추가, 상세 비율과 분리 |
| 공유 위치 속성 불일치 | 공유는 `source`, 유입은 `share_source`, 현재 위치 쿼리는 후자만 조회 | 발생 위치/유입 출처를 별도 표준화 |
| 기존 시간값의 의미 | 이탈 1,598건과 다음 페이지뷰 368건에 이전 체류 시간 존재 | 페이지 시간 대조용으로만 사용 |
| 기존 깊이값 | 이전 본문 도달 속성이 있는 이벤트 1,966건 | 현재 본문 경계·활성 시간의 증거가 아님 |

관찰된 수동 이벤트에는 `page_path`, `cta_location`, `page_type` 누락이 없었다. 다만 값이 채워진 것과 올바른 문맥을 표현하는 것은 다르다. 블로그별 CTA 쿼리는 `page_type=blog_post`와 `slug`를 요구하므로 global 버튼의 실제 블로그 반응이 빠질 수 있다.

## 4. 확정할 수 있는 것과 남은 한계

- 수집·읽기 API 접근과 기본 페이지뷰/CTA 이벤트 존재는 확인했다.
- 30일 페이지뷰 중 블로그 비중과 모바일 비중이 높아 읽기 측정을 우선할 근거가 있다.
- 좋아요·공유는 측정 정상 여부를 먼저 검증해야 하며, 현재 0건을 독자 무관심이나 글 품질 점수로 사용하지 않는다.
- 새 읽기 이벤트와 view 연결 속성은 아직 구현되지 않아 유효 읽기율·반응률을 계산할 수 없다.
- 현재의 적은 문의 이벤트를 이용해 세부 글·채널 순위를 확정하지 않는다.
- 데이터 보관 정책, 요금제/과금, 운영 SDK payload 전체, 실제 예약/통화 결과는 확인하지 않았다.

## 5. 재현용 핵심 쿼리

인증은 기존 서버 조회 경로를 사용하고 환경변수 값을 출력하지 않는다. 아래 쿼리는 데이터 읽기만 수행한다.

```sql
SELECT event,
       count() AS events,
       count(DISTINCT properties.$session_id) AS sessions,
       countIf(properties.$session_id IS NULL
         OR toString(properties.$session_id) = '') AS missing_session
FROM events
WHERE timestamp >= toDateTime('2026-10-14 15:00:00', 'UTC')
  AND timestamp < toDateTime('2026-11-13 15:00:00', 'UTC')
  AND properties.$host IN ('www.born2smile.co.kr', 'born2smile.co.kr')
GROUP BY event
ORDER BY events DESC
LIMIT 60
```

원시 개인별 데이터는 문서에 저장하지 않았다. 다음 단계의 계약과 작업 목록은 [측정 명세 v1](customer-analytics-measurement-contract.md), 전체 배경은 [재설계안](customer-analytics-redesign-plan.md)을 따른다.
